# Условия перехода между этапами

Локальное дополнение от 2026-10-05, выведенное из пользовательского `SKILL.md`.

## Definition of Ready

- Понятны участник, проблема, ожидаемый результат и ближайший объём.
- Требуемое поведение можно выразить наблюдаемыми сценариями.
- Нет нерешённой развилки, приводящей к несовместимым результатам.
- Значимые права, побочные эффекты и границы изменения данных определены.
- Нужный внешний контракт известен либо безопасно изолирован тестовой заменой.
- Для миграции определены совместимость и восстановление.
- Остальные допущения явны и достаточно обратимы для ближайшей части.

Не требовать полноты спецификации всего продукта для небольшой готовой части.
Технические пробелы сначала устранять исследованием, документацией или пробой.

## Implementation gate

- Версии затронутых технологий определены; документация получена через Context7,
  совместимость API проверена. Недоступность и альтернативные официальные
  источники названы явно; реализация не опирается на придуманный контракт.
- Принятые изменения ближайшей части уже внесены в главное ТЗ, а не только в отдельный план или чат.
- Требования ближайшей части ясны, сценарии приёмки существуют.
- Выбран практический способ проверки.
- Зависимости и риски позволяют начать.
- Частью можно управлять и проверить её отдельно.

## Verification gate

- Изменение проверено по согласованным сценариям.
- Необходимые проверки запускались; исходы и ограничения записаны.
- Ошибки исправлены либо явно отмечены как незавершённая работа.

## Definition of Done

- Для затронутых библиотек/фреймворков/API записаны версия и результат проверки
  документации; невыполненный поиск Context7 не выдан за выполненный.
- Нужное поведение работает и критерии приёмки выполнены.
- Значимые тесты и проверки сборки/типов проходят там, где они применимы.
- Ошибки, права и соседние регрессии проверены по риску изменения.
- Документы, решения и статус плана соответствуют реализации.
- Каждое существенное пожелание текущей задачи связано с пунктом главного ТЗ или записью «предложено/отложено/отклонено». Реализация и проверка имеют отдельные статусы.
- Пользовательские изменения сохранены, реальные ограничения названы.

Наличие документов или успешная проверка их заголовков не означает Done.
Если обязательная проверка не выполнена, указывать это прямо.

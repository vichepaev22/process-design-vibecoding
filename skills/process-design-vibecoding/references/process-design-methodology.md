# Методология процесса

Локальное дополнение от 2026-10-05, выведенное из пользовательского `SKILL.md`.

Рабочая цепочка: CONTEXT → PROTOTYPE → USER FEEDBACK → SPEC → MEMORY → CONTRACT → DELIVERY.

1. Изучить инструкции, рабочее дерево, существующие решения и проверки.
2. Сформулировать проблему, участников, результат, границы и ограничения.
3. Уточнить только существенную неопределённость. Использовать известные ответы.
4. Для нового продукта или применимого изменения пути: записать черновик сценария, показать небольшой интерактивный прототип и учесть отзыв. На первом релизе/тестировании продукта один раз выбрать sync/product_only; после product_only работать только в продукте и не поддерживать макет до отдельного запроса. Существующий выбор не переспрашивать. Подробности — `prototype-first.md`.
5. Уточнить спецификацию в принятом проектом формате по результатам отзыва.
6. Проверить Definition of Ready для ближайшей части работы.
7. Составить план небольших законченных частей, каждая с проверяемым результатом.
8. Зафиксировать долговременные решения в документах проекта.
9. Определить сценарии приёмки и подходящие проверки.
10. Реализовать часть, проверить её и обновить план.
11. Проверить Definition of Done и сообщить реальные результаты.

Пользователь определяет продуктовые цели и существенные правила поведения.
Ведущий агент отвечает за интеграцию и окончательную проверку результата.
Сам навык не требует делегирования и не разрешает внешние действия.

При существующих спецификациях, ADR и задачах использовать их вместо новой
параллельной системы документов. Изменения пользователя в рабочем дереве сохранять.

Для небольшой задачи достаточно краткой фиксации ожидаемого поведения,
границ изменения и проверки. Для опечаток процесс целиком не запускать.
Не создавать документы, которые не поддерживают решение или проверку.

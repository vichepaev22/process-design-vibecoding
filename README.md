# Process Design Vibecoding

Навык и переносимый плагин для работы над программными проектами в Codex и
ChatGPT: **контекст → прототип → отзыв пользователя → ТЗ → реализация и проверка**.

## Что изменилось в 1.5.0

Начальный интерактивный прототип и его согласование обязательны. При первом
релизе или тестировании настоящего продукта агент **один раз** спрашивает:
продолжаем обновлять макет вместе с продуктом или дальше правим только продукт?

Выбор сохраняется в проекте. В режиме `product_only` макет заморожен: нет
правок, синхронизации текста, повторных скриншотов, браузерных проверок или
новых согласований макета. Изменения и проверки выполняются в продукте.
Если пользователь уже дал ответ, повторного вопроса нет. Вернуться
к макету можно по отдельному запросу; разовая правка не включает постоянную
синхронизацию. [Подробности](skills/process-design-vibecoding/references/prototype-first.md).

В пакет включены правила начального прототипа из локального обновления 1.4.0.

## Сохраняются правила 1.3.0

Добавлена необязательная визуализация логики проекта. После проработки ТЗ
текущая модель оценивает пользу схемы и при необходимости предлагает один
сценарий: sequence, блок-схему или диаграмму состояний. Предпочтительный первый
вид — sequence: действие пользователя → система → интеграции → результат.
Отдельный вызов модели для оценки не требуется. Отказ или ожидание ответа
не задерживает разработку. Схемы связаны с ТЗ и обновляются вместе с ним;
планируемое поведение явно отделено от проверенного.
[Порядок и тестовый пример](skills/process-design-vibecoding/references/project-visualization.md).

## Сохраняются правила 1.2.0

Перед реализацией навык требует определить технологии и версии, получить
документацию через Context7, проверить совместимость API и использовать
документированные методы. При возможной ошибке API документация проверяется
до выбора исправления. Недоступность инструмента или справки сообщается явно;
неподтверждённые API не придумываются.

Context7 должен быть доступен в среде исполнения. Этот пакет не создаёт
подключение автоматически. При его недоступности агент явно сообщает об этом,
проверяет официальный источник доступным инструментом и не реализует
неподтверждённый контракт. [Подробный порядок](skills/process-design-vibecoding/references/context7-documentation.md).

Сохраняются правила версии 1.1.0:

- Основное ТЗ определяется явно. Запись в дополнительном плане его не заменяет.
- Существенные предложения получают статус: предложено, принято, отложено или
  отклонено. Принятие, реализация и проверка учитываются отдельно.
- Принятые изменения сначала вносятся в ТЗ, приёмку и план. Перед завершением
  агент сверяет все существенные запросы текущей задачи.
- Если ChatGPT не может сохранить исходный документ, он выдаёт обновлённый
  документ или патч и сообщает, что оригинал ещё не изменён.

Для небольших исправлений используется сокращённый процесс. Навык сохраняет
существующие решения и документы, читает только нужные справочные материалы.

## Скачать и установить

[Последний релиз](https://github.com/vichepaev22/process-design-vibecoding/releases/latest)
содержит два архива:

- `process-design-vibecoding-plugin-1.5.0.zip` — плагин с корневым `plugin.json`.
- `process-design-vibecoding-skill-1.5.0.zip` — самостоятельный каталог навыка.

**ChatGPT в браузере:** доступные способы — публикация в каталоге после проверки
OpenAI либо загрузка ZIP/импорт GitHub администратором поддерживаемого рабочего
пространства. Публичный GitHub сам по себе не создаёт запись в каталоге ChatGPT.
[Пошаговая инструкция и ограничения](docs/INSTALL_CHATGPT.md).

**Codex:** скопируйте каталог `skills/process-design-vibecoding` в пользовательский
каталог навыков вашего Codex. Сохраните прежнюю версию перед обновлением.
Также пакет содержит `.agents/plugins/marketplace.json` для импорта как плагина.

После установки попросите: «Примени Process Design Vibecoding к этому проекту.
Основное ТЗ находится в …». Установка не даёт доступ к файлам, аккаунтам и
инструментам, которых нет в выбранном интерфейсе.

## Устройство пакета

`plugin.json` — переносимый формат Agent Plugins с метаданными OpenAI.
`skills/process-design-vibecoding/SKILL.md` — основной алгоритм;
`references/` — пояснения по фазам; `assets/` — шаблоны;
`scripts/` внутри навыка — необязательные локальные помощники.
Пакет не включает собственный MCP-сервер и не запрашивает авторизацию;
поиск документации использует Context7, предоставленный средой исполнения.

```bash
python -m unittest discover -s tests -v
python scripts/build_release.py
```

Помощники требуют Python 3.10+. Проверка структуры и ссылок не доказывает,
что текст ТЗ полно отражает запрос или что продукт работает.
[Результаты проверки релиза](docs/verification.md).

## Публикация плагина

Чтобы пользователь мог найти плагин и нажать «Установить» в общем каталоге,
автор загружает ZIP в [панель публикации OpenAI](https://platform.openai.com/plugins),
выбирает подтверждённую developer identity, проходит автоматические проверки
и модерацию. В этом репозитории подготовлен пакет, а не подтверждённая запись
в публичном каталоге. [Чек-лист подачи](docs/SUBMISSION.md).

Официальные инструкции: [формат пакета](https://developers.openai.com/plugins/build/plugins),
[публикация](https://developers.openai.com/plugins/deploy/submission),
[GitHub-импорт](https://help.openai.com/en/articles/20001504-importing-and-syncing-plugin-marketplaces-from-github).
Сведения проверены 2026-10-10; доступность зависит от аккаунта и рабочего пространства.
